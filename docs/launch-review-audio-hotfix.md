# Invited artist audio upload failure

Production reports received on 15 October 2026 (Brussels) showed “Load failed” and “The string did not match the expected pattern” during private WAV upload. Read-only Cloudflare logs for 14 October UTC confirm successful upload declarations followed by finalization HTTP 503 responses with outcome `exceededCpu` and the message `Worker exceeded CPU time limit`. The failing requests used 1,741–1,955 ms of CPU. The production upload session metadata records WAV files of approximately 63–134 MB, within the existing 500 MiB limit. Storage CORS already allows both production hostnames and the signed upload headers.

The finalizer manually read and wrote every R2 chunk in JavaScript, checking the lease and clock on each iteration. This multiplies application CPU work with file size and chunk count. The fix pipes the native R2 body through a native `FixedLengthStream` into R2, retaining the expected SHA-256 option, exact size check, private staging/final scopes and lease-fenced final key. Cloudflare documents native length enforcement here: https://developers.cloudflare.com/workers/runtime-apis/streams/transformstream/#fixedlengthstream.

A timed renewal keeps the lease alive during slow or stalled transfers, bounded by the upload session expiry. The deadline releases the lease even if storage has not replied, and the Worker schedules cleanup of any late write through waitUntil. Loss of the lease aborts the transfer; an early storage rejection also cancels the readable side so backpressure cannot hang the request. Completion still requires sealed size verification and a valid renewed lease. The database selection and staging cleanup remain behind successful verification. No schema, provider, credential, publication, private-media or size policy changes are made.

The uploader now turns provider HTML failures and browser request exceptions into messages naming the failed upload stage and offering retry. Application JSON rejection messages are preserved, and the selected file remains available for the existing retry button.

Focused evidence: all 31 review-audio and upload-response tests pass. The chunk-overhead regression fails against the previous implementation at 1,027 application clock calls for 1,024 chunks; the new path stays below five. Regressions cover checksum mismatch, short/oversized sources, stalled-I/O lease renewal, lease loss, early storage rejection, expired provider commits with late-write cleanup, completion conflicts and cleanup failures. An isolated native workerd/Miniflare R2 run also copied a synthetic 64 MiB file through the actual service, verified the SHA-256-bearing sealed object and size, renewed the lease and removed staging. It used no production invitation, database writes or artist media. This is local runtime evidence, not a measurement of production CPU consumption or confirmation of the artist's retry.

The maintainer's SOLO exception and authorization to resolve comments, merge and deploy the launch fixes remain active. No Village agents or independent approval claims are used. Production recovery requires the artist to retry after deployment; the actual invited-artist upload is not simulated or fabricated.
