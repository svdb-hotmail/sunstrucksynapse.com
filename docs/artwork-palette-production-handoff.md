# Artwork palette production handoff

The durable palette implementation is now in this PR. The application consumes validated, versioned palettes for the actual selected catalogue artwork; browser extraction has been removed. Generated palettes are stored per asset with source provenance and lease fencing, separately from human overrides. Precedence is asset override, reviewed slug identity, generated palette, then the selected site skin. Routes, playback and theme/skin controls retain their existing contracts.

The private encoder provides deterministic bounded JPEG/PNG/WebP/AVIF extraction outside page requests. A disabled-by-default database producer captures new or replaced final publishable artwork across upload/publication paths. The opt-in `npm run deploy:palettes` command applies migrations, deploys the encoder, builds/deploys the consumer, enables the producer and runs a metadata-only backfill dry-run. It does not run an existing-artwork write backfill.

Follow [the exact rollout, backfill, verification and rollback runbook](artwork-palette-deployment.md). Existing production artwork writes require a reviewed dry-run and human approval before the explicit production write command. Cloudflare dashboard build/deploy commands must be changed by an operator as described there; no account-side settings or production data were changed during implementation.

Legacy static SVG artwork keeps the reviewed identity/skin fallback and records an unsupported-source failure if generation is requested. Static supported images are read only by an explicitly requested write backfill, confined to the checkout's public directory, and verified against database size and checksum before using the same versioned local extractor. R2 jobs are queued for the private background encoder.
